# Misspelling Platform 阶段性进展报告（2026-03-07）

## 1. 文档说明

- 文档类型：阶段性研发进展说明（供导师/组会汇报）
- 更新时间：2026-03-07
- 适用版本：当前主干可部署版本（Ubuntu + Docker + Nginx 线上环境）
- 报告重点：系统完成度、算法成熟度、未完成项与下一阶段计划

---

## 2. 项目目标与当前阶段定位

### 2.1 项目目标

本项目目标是构建一个面向错拼行为分析的研究平台，支持：

1. 错拼词候选生成与管理  
2. 时序数据拉取与任务化分析  
3. 多算法分析结果展示与追溯  
4. 项目管理、中观分析与报告导出  
5. 管理端运维与审计能力

### 2.2 当前阶段定位

当前系统已完成“工程框架可用 + 研究接口打通”的阶段目标，整体可稳定运行并支持演示。  
但算法核心模块整体仍处于“初步接入/响应验证”阶段，尚未进入“正式科研实现与严格评估”阶段。

---

## 3. 系统整体完成情况（工程侧）

### 3.1 部署与运行环境

- 后端、数据库、Redis、Worker 已在 VPS 通过 Docker Compose 稳定运行。
- 前端已构建并通过 Nginx 对外提供服务（同域反代后端）。
- 域名访问链路与 HTTPS 已打通，可进行外网访问和功能验证。

### 3.2 后端基础能力

- 已形成 FastAPI + Celery 的任务化后端架构。
- 核心 API 路由已建立：
  - 鉴权（登录/注册/会话）
  - 任务创建/查询/事件/产物
  - 词典与变体建议
  - 数据源拉取（GBNC）
  - 项目管理与报告导出
  - 管理端诊断与审计
- 数据库 schema 已演进到多租户与企业扩展阶段（用户、任务、时序、项目、分析、报告等表结构齐备）。

### 3.3 任务闭环能力

- 已支持任务全生命周期闭环：
  - 创建（QUEUED）
  - 执行（RUNNING/PROGRESS）
  - 完成（SUCCESS/FAILURE）
  - 事件记录（task_events）
  - 产物落盘/登记（task_artifacts）
- 已支持任务重试、列表过滤、删除与报告导出流程。

### 3.4 数据与词典链路

- 已接入 GBNC 拉取通道，支持缓存命中与降级回退策略。
- 已建立错拼建议优先级策略（**已按需求完成**）：
  1. 优先使用自建错拼词典；
  2. 词典未命中时调用大模型建议；
  3. 大模型不可用时回退启发式规则。
- 该策略已在后端服务逻辑中固化，不是前端临时拼接逻辑。
- 已在前端变体工作台加入“错误变体分值计算与排序”能力（启发式）：
  - 基于编辑距离（Levenshtein）与长度差惩罚；
  - 基于首字母匹配、公共前缀长度给予加分；
  - 输出 0-100 的置信分值用于候选排序与 Top-N 快速选择。

### 3.5 前端与交互框架

- 研究端与管理端页面框架已基本搭建完成：
  - Dashboard / Tasks / Word Analysis / Variants / Projects / Analytics
  - 三类算法页（Causal / Steady / DeltaT）
  - Time Series / Artifacts / Reports / Settings
  - Admin Dashboard / Users / Audit Logs / Data Sources
- 页面已能完成主要操作链路与结果展示，不再是纯静态原型。

### 3.6 安全与审计（当前基线）

- 已接入账号鉴权与角色控制（user/admin）。
- 审计日志已覆盖关键管理与数据操作。
- 敏感入口已接入 Turnstile 防刷验证（登录与高成本任务提交链路）。

## 4. 算法模块成熟度评估（研究侧）

> 说明：以下评估按照“研究可用性”口径，不按“接口是否可调用”口径。

| 模块 | 当前状态 | 成熟度判定 | 结论 |
|---|---|---|---|
| PCMCI 因果网络 | 已接入任务与页面，可返回结果结构 | 初步接入 | 未完成正式算法接入与实验验证 |
| MR/NMR 稳态分析 | 已接入任务与页面，可返回指标预览 | 初步接入 | 未完成正式算法接入与参数定标 |
| DeltaT 偏差分析 | 已接入任务与页面，可返回事件预览 | 初步接入 | 未完成正式算法接入与统计验证 |
| 仿真模块（simulation） | 可运行，但当前为预设 demo 数据链路 | Demo | 非正式仿真模型实现 |
| 中观聚类分析 | 已有 baseline 聚类流程与页面 | 基线占位 | 算法层面尚未完成 |

### 4.1 关键说明

1. 三类算法当前重点是“接口打通、任务编排、结果 envelope 统一、前端联调”。  
2. 当前版本存在 stub/fallback 机制，目的是保证系统演示稳定，而非证明算法完成度。  
3. 因此，当前版本可以证明“平台可承载算法任务”，但不能证明“算法研究结论已成立”。

## 5. 已完成与未完成边界（导师关注项）

### 5.1 已完成（可明确汇报）

1. 平台架构、部署链路、任务闭环、数据落库、页面体系已基本完成。  
2. 三类算法任务接口、参数传递、结果归档、前端展示流程已联通。  
3. 错拼建议已实现“词典优先，LLM 补充”的策略。  
4. 管理端基础能力（用户、审计、数据源、诊断）可运行。  

### 5.2 未完成（需明确说明）

1. 三类算法尚未完成正式科研实现、参数校准与有效性验证。  
2. 仿真模块目前为 demo，不可作为实验结论依据。  
3. 中观聚类目前是 baseline 占位，不是最终研究算法方案。  
4. 缺少系统化实验评估体系（对照、消融、统计显著性、误差分析）。  
5. 自动化测试与回归测试覆盖仍不足（当前以集成 smoke 为主）。

---

## 6. 当前系统的主要不足

1. **研究严谨性不足**：算法“可跑”不等于“可发表/可答辩”。  
2. **评估体系薄弱**：缺少标准数据集与固定评价协议。  
3. **变体分值当前为启发式评分**：尚未完成概率校准与标注数据验证，暂不能作为严格统计置信度。  
4. **模块语义不一致风险**：前端文案、结果字段与研究定义需进一步统一。  
5. **可复现实验链路待固化**：需要统一实验配置、随机种子、版本快照。  
6. **工程质量仍需提升**：异常场景覆盖、自动化测试、监控告警有待完善。

---

## 7. 下一阶段计划（建议执行顺序）

### 7.1 第一优先级：算法正式化

1. 明确三类算法的正式实现边界（输入、假设、输出、失败条件）。  
2. 完成算法参数校准与数据前处理规范。  
3. 去除“仅演示”逻辑对结论路径的干扰，保留可控降级但不用于研究结果统计。  

### 7.2 第二优先级：评估体系建设

1. 建立统一实验协议（数据切片、时间窗、指标定义）。  
2. 增加对照实验与消融实验。  
3. 输出统计检验与误差分析报告模板。  
4. 对变体评分模块开展校准验证（与人工标注一致性、排序质量指标）。  

### 7.3 第三优先级：仿真与中观分析补全

1. 仿真模块从 demo 升级为可解释、可参数化模型。  
2. 中观聚类从 baseline 升级为研究方案，并给出评价指标。  
3. 完成算法结果与业务解释链条的统一表达。  

### 7.4 第四优先级：工程质量提升

1. 增加后端核心路径自动化测试（鉴权、任务、数据源、报告）。  
2. 增加前端关键交互回归测试。  
3. 完善监控/日志分级与故障告警策略。  
4. 固化版本发布流程与变更记录模板。

---

## 8. 可交付性结论（阶段性）

从平台工程视角，当前版本已具备“可部署、可演示、可扩展”的交付条件。  
从研究算法视角，当前版本属于“接口打通与初步验证”阶段，不宜作为最终算法结论版本。  

**建议在下一阶段以“算法正式化 + 评估体系建设”为主线推进，形成可答辩级别的研究证据链。**
